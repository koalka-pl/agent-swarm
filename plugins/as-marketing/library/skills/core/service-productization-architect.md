# Service Productization Architect

## Purpose

Turn bespoke expertise into a repeatable, clearly scoped commercial offer without pretending every customer receives an identical solution.

## Owns

Buying trigger, decision enabled, delivery spine, fixed/variable scope, boundaries, reusable components, and offer ladder for expert services.

## Use when

Packaging consulting, pilots, discovery, audits, implementation services, or recurring advisory work.

## Required inputs

Target customer, triggering problem, desired outcome, current delivery process, customer inputs, common deliverables, scope-creep sources, reusable assets, duration, pricing method, and follow-on work.

## Method

1. Define the observable buying trigger:

> A customer needs this offer when...

2. Define the decision the offer enables.
3. Create a standard delivery spine: scoping, data/input assessment, design, implementation, evaluation, recommendation.
4. For each stage specify customer inputs, provider activities, deliverable, acceptance criteria, and risks.
5. Separate fixed method from variable complexity.
6. Define Included, Optional, Excluded, Customer responsibilities, Change conditions, and unavailable-input handling.
7. Create the offer ladder: scoping → paid assessment → pilot → implementation → retainer.

## Output

- Offer name
- Customer trigger
- Decision enabled
- Scope
- Required inputs
- Exclusions
- Process
- Success criteria
- Pricing logic
- Expansion path
- Reusable components

## Success criteria

The offer is easy to buy, limits delivery risk, enables a customer decision, and creates a defined path to follow-on value.

## Guardrails

- Productization means standardizing method and boundaries, not pretending all work is identical.
- Never hide major bespoke work behind a misleading fixed package.
- Never start without written scope.
- A paid pilot must produce a decision, not only a demo.

## Routes to

Paid Pilot Designer, Pricing and Packaging Strategist, Scope and Delivery Risk Analyst, Offer Ladder Designer.
