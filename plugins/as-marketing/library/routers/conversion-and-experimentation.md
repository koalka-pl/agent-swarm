# Conversion & Experimentation Router

## Purpose
Select exactly one owner skill for conversion diagnosis, landing-page strategy, form friction, message continuity, objections and proof, or controlled experimentation.

## Required context
Audience, traffic or entry source, page/flow, offer, desired action, current performance, available proof, known objections, measurement quality, sample size, and implementation constraints.

## Routing
- Write or rewrite conversion-focused marketing copy from approved strategic inputs → Conversion Copywriter
- Map conversion paths across a multi-page journey → Website Conversion Architect
- Diagnose an underperforming marketing page and prioritize hypotheses → Marketing Page CRO Auditor
- Design one post-click conversion argument for one source, audience, offer, and action → Landing Page Strategist
- Reduce capture friction while preserving qualification → Form Optimization Specialist
- Compare source promise with destination experience → Campaign Message-Match Analyst
- Map doubts to appropriate evidence → Objection and Proof Strategist
- Design a controlled test and decision protocol → Experiment Design Strategist
- Interpret a completed controlled test → A/B Test Analyst

## Exclusions
Website design and code implementation remain outside this starter. Paid-campaign optimization is excluded. Conversion Copywriter is included as an explicit exception; other channel-specific content writers remain outside the core.

## Selection rules
1. Keep diagnosis, hypothesis, implementation, and measured result distinct.
2. Choose one owner skill.
3. Audit before redesign when the cause is unclear.
4. Do not recommend A/B testing when traffic cannot support a useful decision; use qualitative validation or a staged rollout instead.
5. Route tracking implementation to Measurement & Operations.
6. Route positioning, offer, or customer-research gaps upstream.

## Output
Selected owner skill, rationale, required inputs, evidence gaps, validation method, excluded routes, and next routing decision.

## Guardrails
Do not call early test results, invent conversion data, optimize proxy metrics without business context, or treat observed correlation as causal evidence.
